# Accessibility of the app shell

Audit of `@orbitrace/app` against WCAG 2.1 level AA, done for issue #13 on 27 Nov 2026. It
covers the app shell: header, session picker, orrery host, playback controls, timeline,
inspector, event feed, live marker, alerts, and the loading, empty and error pages. The
drawing inside the orrery canvas belongs to `@orbitrace/renderer` and is covered only where the
app gives it a text alternative.

**No screen reader was used.** No person checked this with NVDA, JAWS, VoiceOver, Narrator or
TalkBack. Everything below comes from code review, automated checks and one scripted run in
headless Chrome. The list in [Still to check with a screen reader](#still-to-check-with-a-screen-reader)
needs a person.

### What the automated checks found

axe-core in the test suite reported **no** failures on the app as it was before this ticket, and
none after. Every finding below came from review or from the browser run. Treat a passing axe
run as a floor, not as proof.

**Correction after review.** The first browser run used only the demo, which has no session
list, and only window sizes where the inspector fit. An independent review then found four
problems that run missed: the open session list overflowed at 320 px and was cut off in the
wide layout at 200% zoom (finding 15), lane names were cut off with an ellipsis at 200% zoom and
under 1.4.12 text spacing (finding 23), call kinds on the lanes differed by colour alone
(finding 8), and at 1280 by 560 px axe reported `scrollable-region-focusable` as needs review on
the inspector (finding 24). The first version of this file said contrast was the only needs
review result and that no control clipped its text under text spacing; both were wrong.

In the headless Chrome run after those fixes: axe reported no violations in any state (demo,
agent selected, session list open at 320, 840, 900 and 1280 px, inspector at 1280 by 560 px).
Its only "needs review" result was `color-contrast` on timeline rows scrolled out of view, which
it cannot measure; those colours are covered by `test/contrast.test.ts`.
`scrollable-region-focusable` no longer appears. The page was exactly as wide as the window at
every size above, and scrolled vertically at 1280 by 256 px. With the session list open, no
label was cut and nothing in the list lay outside the window: at 320 px the list spanned 16 to
304 px, at 840 px 302 to 824 px. No lane name was cut at 320, 640 or 1280 px (at 320 px two rows
grew from 24 to 26 px; at 640 px the label column stayed 148 px). With WCAG 1.4.12 text spacing
at 1280 px, none of the 38 visible buttons, lane names and legend entries clipped its text. Each
Tab stop showed a 2 px `ion` outline, and the inspector's outline is drawn inside its edge. No
control was smaller than 24 by 24 px. With reduced motion the demo did not start playing.

## Still to check with a screen reader

A person should check these with at least NVDA with Firefox or Chrome on Windows and
VoiceOver with Safari on macOS, and once inside the VS Code extension:

1. The table after the canvas: reached by table navigation and by reading on from the canvas;
   caption and headers read; it is **not** announced on its own while the replay plays.
2. The live region: one announcement when a replay loads; live session state changes and new
   agents are announced once, politely, and not repeated on every snapshot.
3. The Replay position slider: while playing, value changes at most once per replay minute;
   paused, arrow keys report the exact time. Space on the slider plays and pauses.
4. The session button announces expanded and collapsed; Escape closes the list; focus returns
   to the button after choosing.
5. Focus moved to the inspector heading after Clear selection, and to Open file after Dismiss,
   is announced.
6. Lane labels announce "_callsign_, N failed" and the pressed state; Up and Down move
   between them.
7. In a VS Code editor tab: Space, arrows, Home, End and Escape reach the app and are not taken
   by the editor; the focus outline looks as in a browser; turning on the editor's reduce-motion
   setting stops autoplay; the editor's screen reader mode (`vscode-using-screen-reader` on the
   body) changes nothing for the worse.
8. Windows High Contrast (forced colours): focus outline, selected lane outline, and the live
   marker text remain visible; the call marks on the lanes and in the legend keep their
   heights.
9. 200% and 400% zoom in a real browser window, and Firefox text-only zoom, with the session
   list open and a long project label.
10. Safari: Tab reaches the inspector region after the last lane label, and the arrow and Page
    keys scroll it. When it takes focus, a screen reader reads its name ("Session" or "Agent")
    and does not read the whole panel in one go.
11. The timeline legend ("Tool call marks") reads as a short list and does not get in the way
    when moving from the controls to the lanes.
12. The canvas: spawn flash and warp against WCAG 2.3.1, and the contrast of canvas labels drawn
    over glows (both renderer, not measured here).

## Not covered

- The canvas drawing itself (labels, glows, label overlap) belongs to `@orbitrace/renderer`.
- Dropping a file into an editor tab: the editor handles drops before the page sees them.
- WCAG 2.2 criteria other than target size.

## Running the checks

From the repository root, `npm test` runs every check above that is committed. The headless
Chrome run is not part of the suite: it needs a local Chrome. To repeat it:

1. `npm run build`, then serve `packages/app/dist` from a small local server that also answers
   the loopback routes with invented data: `POST /api/rpc` returns three invented sessions for
   `listSessions` (project labels of about 19, 28 and 40 characters, one with no hyphens) and
   the bundled demo replay for `loadReplay`; `POST /api/live` writes one `live` line with the
